# Ricochet Tank P0-P1 开发流程

**状态：** 已批准

**日期：** 2026-07-10

**目标：** 在保留现有原创道具的前提下，先恢复可发布的工程基线，再逐步补齐《坦克动荡 2》经典本地玩法。

## 1. 范围与原则

本轮工作分为 P0 和 P1。P0 只解决发布基线、调试残留和最低工程规范；P1 增加三人本地模式、暂停与比赛设置、统一武器输入，并补齐经典武器及其自伤风险。

全程遵循以下约束：

- 保留 Shield、Rapid Fire、Double Shot、Laser、Rocket、Mine、Shotgun 等现有道具。
- 新增 Death Ray、RC Missile 和 Frag Bomb。
- 不在本轮实现在线房间、账号、排行榜、皮肤、地图编辑器或移动端控制。
- 不以一次性重写替换现有游戏；采用可回滚、可独立验收的增量改造。
- 新行为必须先有失败测试，再写最小实现。
- 每个 Git 提交只包含一个可描述、可验证的阶段成果。
- 测试、类型检查、生产构建或浏览器冒烟任一失败时，不得提交该阶段代码。

## 2. 总体实施方案

采用增量兼容式改造：

1. 恢复类型安全和生产构建。
2. 建立统一检查命令和发布文档。
3. 将固定双人逻辑改为玩家列表驱动。
4. 增加第三名鼠标玩家和多人胜负结算。
5. 增加暂停与比赛设置。
6. 统一普通射击和主动武器输入。
7. 新增经典武器。
8. 调整现有武器，使其恢复原版的反弹、自伤和目标切换风险。

不选择整体重写 `GameScene`，因为现有 AI、道具、碰撞、声音和回合系统已经可运行。新增边界应逐步从场景中抽离，同时保持每一步都能运行。

## 3. P0：恢复可交付工程基线

### 3.1 类型和构建

- `src/config.ts` 是 `GameSettings` 与 `AIDifficulty` 的唯一来源。
- 删除 `GameScene.ts` 中重复的 `GameSettings`。
- 模式值统一为 `local | ai`，不得再出现 `pvp`、`vs-player` 或 `vs-ai`。
- 难度字段统一为 `aiDifficulty`。
- AI 难度配置只保留一个接口和一套字段名。
- AI 状态集合显式声明为 `Map<AIStateType, AIState>`。
- 修复测试中对旧字段的引用。

### 3.2 工程检查

在 `package.json` 中提供：

- `typecheck`：执行 `tsc --noEmit`。
- `test`：执行完整 Vitest 测试。
- `build`：执行类型检查和 Vite 生产构建。
- `check`：顺序执行类型检查、测试和生产构建。

### 3.3 调试和发布收尾

- AI 路径只在显式 `DEBUG_AI_PATHS` 开关启用时绘制，默认关闭。
- 补充 favicon，消除浏览器 404。
- 添加 README，记录安装、开发、检查、构建和全部控制方式。
- 浏览器冒烟覆盖主菜单、本地双人、AI 难度选择、AI 对局和返回菜单。

### 3.4 P0 验收标准

- `npm run typecheck` 退出码为 0。
- `npm test` 全部通过。
- `npm run build` 退出码为 0。
- 开发服务器中本地双人和 AI 模式均可进入。
- 浏览器控制台没有应用错误或缺失静态资源。
- AI 模式默认不显示调试路径。

## 4. P1-A：多人和比赛框架

### 4.1 玩家模型

游戏逻辑从固定的 P1/P2 字段逐步调整为玩家列表。每名玩家至少包含：

- `playerId`
- 控制器类型：`keyboard | mouse | ai`
- 坦克引用
- 比分
- 显示名称与颜色

双人模式继续使用现有键盘控制；三人模式增加第三辆坦克、第三个出生点和第三份比分。

### 4.2 第三名鼠标玩家

- 鼠标位置决定目标朝向。
- 坦克逐帧转向鼠标，而不是瞬间旋转。
- 鼠标与坦克距离超过死区时向鼠标方向前进。
- 鼠标左键触发射击或当前主动武器。
- 鼠标位于死区内时坦克停止移动，但仍可调整朝向和射击。

### 4.3 多人回合结算

- 回合目标是成为最后存活的坦克。
- 只有一名坦克存活时，该玩家得 1 分。
- 所有坦克同帧死亡时为平局，不加分。
- 达到 `SCORE_TO_WIN` 的玩家赢得整场比赛。
- 计分和 HUD 必须同时支持两名或三名玩家。

## 5. P1-B：暂停与比赛设置

Esc 不再立即返回菜单，而是打开暂停层。暂停层包含：

- 继续游戏
- 重新开始当前比赛
- 返回主菜单
- 音效开关
- 道具开关
- 当前模式的完整控制说明

暂停时停止坦克、子弹、导弹、地雷、道具计时器、AI 和回合计时器。恢复后不得产生额外的时间跳跃。

## 6. P1-C：统一武器输入

### 6.1 射击优先级

每名玩家只需要一个主要射击输入：

1. 持有主动武器时，射击键释放主动武器并消耗它。
2. 没有主动武器时，射击键发射普通子弹。
3. 被动道具自动生效，不占用额外输入。

现有 `E` 和 `.` 在本轮保留为兼容快捷键，但菜单和 README 以统一射击键为主。兼容键不得绕过冷却、暂停或武器消耗规则。

### 6.2 被动道具

- Shield：维持一次伤害吸收和持续时间。
- Rapid Fire：维持普通子弹冷却缩短。
- Double Shot：维持普通子弹双发。

主动武器与被动道具继续共用一个持有槽；拾取新道具替换旧道具。

## 7. P1-D：经典武器

### 7.1 Death Ray

- 按下射击后进入蓄力。
- 蓄力期间坦克不能移动或旋转。
- 蓄力完成后射线穿过内部墙体，到外边界停止。
- 射线可击毁路径上的多辆坦克，包括发射者在路径重新穿过自身时。

### 7.2 RC Missile

- 发射后玩家控制导弹的转向。
- 导弹存在期间，发射者坦克不能移动或射击。
- 导弹可反弹，并在命中坦克、超过寿命或达到反弹上限时销毁。
- 导弹可击中任意坦克，包括发射者。

### 7.3 Frag Bomb

- 第一次射击发射炸弹。
- 再次按射击键、命中坦克或达到触发条件时爆炸。
- 爆炸产生多枚碎片。
- 碎片命中墙体后停止或销毁，不穿墙。
- 爆炸和碎片可伤害任意玩家，包括发射者。

## 8. 现有经典武器调整

### 8.1 Laser

- 拾取后显示反弹路径预览。
- 正式射线沿预览路径传播。
- 反射后允许命中发射者。

### 8.2 Homing Missile

- 发射后先自由飞行。
- 延迟锁定距离最近的存活坦克。
- 飞行中允许切换到更近目标。
- 发射者也是合法目标。
- 撞墙时按规则反弹，不立即销毁。

### 8.3 Mine

- 每名玩家最多保留三枚。
- 放置后对其他玩家隐藏。
- 被坦克触发后显形并爆炸。
- 爆炸产生碎片并允许自伤。

## 9. 代码边界

逐步引入以下职责边界：

- `PlayerController`：把键盘、鼠标和 AI 转换为统一 `PlayerInput`。
- `MatchManager`：维护玩家、比分、存活状态和回合胜负。
- `WeaponSystem`：决定普通射击、主动武器、武器消耗和冷却。
- `PauseOverlay`：暂停界面、设置和恢复流程。
- `DeathRay`、`RCMissile`、`FragBomb`：各自维护生命周期和表现。

`GameScene` 继续负责 Phaser 场景生命周期和系统编排，不再新增独立武器的详细规则。

## 10. 测试策略

### 10.1 TDD 循环

每项行为严格执行：

1. 写一个描述目标行为的最小测试。
2. 运行目标测试，确认它因行为尚未实现而失败。
3. 写使测试通过的最小实现。
4. 再次运行目标测试。
5. 运行相关测试集。
6. 重构并保持测试为绿色。

### 10.2 测试层次

- 纯逻辑单元测试：输入映射、胜负判定、武器状态、目标选择、反弹和碎片生成。
- 对象测试：Death Ray、RC Missile、Frag Bomb 的生命周期。
- 场景测试：模式选择、玩家创建、暂停恢复和回合清理。
- 浏览器冒烟：菜单到对局的关键路径和控制台错误。

## 11. 提交与审查流程

计划提交边界：

1. `docs: add P0-P1 development workflow`
2. `fix: restore type-safe production build`
3. `chore: add project checks and release documentation`
4. `feat: add three-player local match support`
5. `feat: add pause and match settings`
6. `refactor: unify standard and power-up weapon firing`
7. `feat: add classic special weapons`
8. `fix: restore classic weapon self-damage behavior`

每次代码提交前必须执行：

```powershell
npm run typecheck
npm test
npm run build
```

涉及可见交互时，还必须启动开发服务器并完成对应浏览器冒烟。提交前检查 `git diff --check`、`git diff` 和 `git status --short`，确认没有临时截图、日志、调试开关或无关改动。

完成主要阶段后进行代码审查；Critical 和 Important 问题必须在进入下一阶段前解决。

## 12. 完成定义

P0 完成意味着仓库可稳定测试和构建，开发模式与生产构建行为一致，没有默认调试残留。

P1 完成意味着玩家可以选择本地双人或三人比赛，第三名玩家可使用鼠标完成移动和射击；游戏具有真正的暂停流程；普通射击与主动武器共用主要射击输入；新增经典武器可用；激光、追踪导弹和地雷具备反弹、目标变化及自伤风险；全部自动化检查和浏览器验收通过。
